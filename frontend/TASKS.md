# Frontend tasks

Do these one at a time, in the order `../PLAYBOOK.md` gives. Before you plan, look up the topics in the library with `node ../library/find.mjs` and `node ../library/show.mjs`.

- **Needs backend N:** wait until that backend task is ticked.
- **Done when:** `npm run build` and `npm run lint` pass, and the change works in the browser against the running backend.

## Changelog

- Starter: resources, availability, booking, my bookings with cancel, themes, mobile layout.
- Task 1: Button, Card, Field, Notice and Skeleton components; skeletons for resources, slots and bookings; toasts after booking and cancelling (polite live region, reduced-motion aware).
- Task 2: slot legend; Day/Week toggle with a 7-day × times week view (URL state, free cells open the day with the slot chosen); availability refreshes every 60 s and on focus; a chosen slot taken meanwhile is unselected with a notice.
- Task 3: booking details page `#/b/:id` (status, cancel, Add to calendar `.ics` in UTC); linked from the success notice, the toast and My bookings; one friendly message per error code in `lib/errors.ts`, with the trace id shown as a reference.
- Task 4: TanStack Query replaces useApi: keyed queries (availability fresh 30 s, refetched every 60 s and on focus), book/cancel mutations invalidate that day and My bookings, optimistic cancel with rollback and toasts; 4xx never retried.
- Task 5: `src/lib/api.generated.ts` generated by openapi-typescript (`npm run gen:api` / `gen:api:file`); `api.ts` re-exports the generated types and has no hand-written ones.
- Task 6: sign up, sign in and sign out pages (field errors from the API, autocomplete), account menu in the top bar, "your bookings were moved" toast, any 401 → sign in → back (in-app `next` only).
- Task 7: staff schedule at `#/staff[/date]`: a timeline with resources as columns, bookings as buttons, closures and closed hours; a panel offering exactly the API's allowed actions (completed, no-show, cancel with a reason); block time from real slot starts; Schedule link for staff only; shared status labels.
- Task 8: admin pages at `#/admin/…`: courts and rooms (add, edit, weekly hours, delete), whole-day closures incl. holidays, booking rules, read-only audit log; every form shows the API's field errors next to the fields; Admin link for admins only.
- Backend 11 follow-up: booking holds the slot and confirms it in one go (`api.confirm`); `pending`/`expired` labels, `hold_expired` message; expired holds hidden on the staff timeline. The countdown and payment step are task 9.
- Backend 12 follow-up: confirming pays the deposit with the fake provider's approved test token (`tok_visa`) until task 9 adds the payment step; `Deposit`/`Money` types; messages for the payment codes.
- Task 9: booking makes a hold and opens the payment step at `#/b/:id`: countdown on the API's clock (from the Date header) with polite announcements, the deposit, a test-card picker for every fake-provider outcome, pay and confirm (402 shows why, 503 offers a safe retry), release; when the hold runs out the page asks the API and explains it (released, charged or not, refunded); live holds in My bookings with "Pay and confirm"; a new page starts at the top.
- Backend 13 follow-up: an optional Email field when booking (remembered; signed-in customers default to their account address, the API's field error shows next to it); the booking and checkout show where emails go.
